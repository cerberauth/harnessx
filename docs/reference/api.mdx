## Types

### Target

What you're scanning. The engine never interprets it; it is passed unchanged to every check and reporter.

```go
type Target struct {
  URL      string
  Host     string
  Metadata map[string]string
  Data     any
}
```

### Resource

Discovered by checks (via `Result.Resources`) and consumed by per-resource checks that depend on them. Resources are identified by `ID` across a run: when several checks emit the same `ID`, per-resource checks still run once for it, against the version kept by the engine's `ResourceMergeFunc` (the first one discovered, by default; see `WithResourceMerge`).

```go
type Resource struct {
  ID       string
  URL      string
  Method   string // defaults to GET in NewRequestFromResource when empty
  Metadata map[string]string
  Data     any // read back with ResourceDataAs
}
```

### CheckID

Unique identifier for a check. A defined type over `string`, not an alias.

```go
type CheckID string
```

### CheckScope

How often a check runs. The zero value is `ScopeGlobal`.

```go
type CheckScope int

const (
  ScopeGlobal      CheckScope = iota // runs once
  ScopePerResource                   // runs once per resource known when its level starts
)
```

### Observation

An issue or noteworthy outcome found by a check. A check need not set `CheckID`, `ResourceID` or `Variant`: the engine fills each one left blank with the check, the resource (for a per-resource check) and the variant (for a check with `Variants`) that produced it, so `ScanSummary.Observations` always says where each finding came from.

```go
type Observation struct {
  CheckID     CheckID
  ResourceID  string
  Variant     string
  Title       string
  Description string
  Evidence    string
  Metadata    map[string]string
}
```

### Result

The result of a single check execution (one resource, for a per-resource check). The engine sets `CheckID`, `ResourceID` and `Duration` on the results it records.

```go
type Result struct {
  CheckID      CheckID
  ResourceID   string
  Observations []Observation
  Resources    []Resource    // discovered resources, visible to later levels
  Skipped      bool
  SkipReason   string
  Duration     time.Duration
  Metadata     map[string]string
  Data         any           // output for later checks, see GetData / DataAs
  Err          error         // non-nil marks the check as failed
  Attempts     []Attempt     // one entry per variant, for checks that use Variants
}
```

Observations report findings and do not by themselves fail a check; only a non-nil `Err` does.

`Result.Status()` classifies a result as one of four `ResultStatus` values. An error wins over everything else, then skipped, then observations:

```go
const (
  StatusPassed  ResultStatus = "passed"  // ran, no error, no observations
  StatusFailed  ResultStatus = "failed"  // ran without error but made observations
  StatusSkipped ResultStatus = "skipped"
  StatusError   ResultStatus = "error"   // returned an error or panicked
)

func (r Result) Status() ResultStatus
```

`IfCheckPassed`, the scan summary counts and the OpenTelemetry `status` attribute all use it.

### Attempt / VariantMode

The outcome of a single variant of a `Variants` check — see [Check](#check) and [NewVariantCheck / NewVariantResourceCheck](#newvariantcheck--newvariantresourcecheck).

```go
type Attempt struct {
  Variant      string
  Observations []Observation
  Resources    []Resource
  Skipped      bool
  SkipReason   string
  Duration     time.Duration
  Data         any
  Err          error
}

type VariantCheckFunc func(ctx context.Context, target Target, variant string, store ResultStore) (Result, error)
type VariantResourceCheckFunc func(ctx context.Context, target Target, resource Resource, variant string, store ResultStore) (Result, error)

type VariantMode int

const (
  VariantsSequential VariantMode = iota // default: variants run one at a time, in order
  VariantsParallel                      // variants run concurrently
)
```

A panic inside one variant's run function is recovered onto that variant's `Attempt.Err` — it does not abort the other variants or the rest of the scan.

### Snapshot / Baseline

A captured response, reduced to what a comparator needs. `Baseline` is an alias for `Snapshot`, used when it's held up as the expected/reference value.

```go
type Snapshot struct {
  StatusCode int
  Header     http.Header
  Body       []byte
  Duration   time.Duration
  Data       any

  Truncated bool   // Body was cut at probe.DefaultMaxBodySize
  BodyHash  uint64 // SimHash of Body, set by CaptureSnapshot; 0 means unset
}
type Baseline = Snapshot
```

### BaselineSource

Resolves the baseline for a resource. `ok=false` means no baseline is available and the comparison check skips.

```go
type BaselineSource func(ctx context.Context, target Target, resource Resource, store ResultStore) (Baseline, bool)

func StaticBaseline(b Baseline) BaselineSource
func BaselineFromResource() BaselineSource
func BaselineFromCheck(id CheckID) BaselineSource
```

### BaselineComparator

Compares a baseline against a freshly captured snapshot and returns any resulting `Observation`s. An empty result means no deviation.

```go
type BaselineComparator func(baseline, current Snapshot) []Observation

func CompareStatusCode(baseline, current Snapshot) []Observation // default comparator
func CompareStatusAndLength(tolerance float64) BaselineComparator
func CompareSimilarity(threshold float64) BaselineComparator
func SimHash(body []byte) uint64
```

- `CompareStatusCode` flags any change in status code.
- `CompareStatusAndLength(tolerance)` flags a status change, or a body length outside ±`tolerance` of the baseline's (`0.1` allows ±10%). A negative tolerance is treated as `0`.
- `CompareSimilarity(threshold)` flags a status change, or a body whose similarity to the baseline's falls below `threshold` (0..1, 1 = identical). Similarity is `1 −` the normalised Hamming distance between the two bodies' `SimHash`es, so a catch-all "not found" page that echoes the requested path scores high while a genuinely different page scores low. A typical threshold is 0.8–0.95. A non-zero `Snapshot.BodyHash` is used instead of hashing `Body`.
- `SimHash` returns a 64-bit locality-sensitive fingerprint over the case-insensitive letter/digit tokens of `body`; an empty or token-free body hashes to `0`.

Length and similarity are computed on `Snapshot.Body`, which is capped by the probe's body limit — check `Snapshot.Truncated` before trusting them on very large responses.

### Request building

`probe` package. `NewRequest` is the single entry point for building an outgoing HTTP request; small named `RequestMutator` functions compose onto it to shape headers, cookies, query params, or credentials.

```go
type RequestMutator func(*http.Request) error
type RequestBuilder func(ctx context.Context) (*http.Request, error)

func NewRequest(ctx context.Context, method, target string, body io.Reader, mutators ...RequestMutator) (*http.Request, error)

func WithHeader(name, value string) RequestMutator
func WithCookie(cookie *http.Cookie) RequestMutator
func WithQuery(name, value string) RequestMutator
```

`NewRequestFromResource` (root `harnessx` package) is a convenience over `NewRequest` for a `Resource`, defaulting to `GET` when `Resource.Method` is empty:

```go
func NewRequestFromResource(ctx context.Context, r Resource, mutators ...probe.RequestMutator) (*http.Request, error)
```

### Credential mutators

`probe` package. One thin `RequestMutator` per real-world auth use case — place an arbitrary secret/credential (a token, API key, session ID, basic-auth pair, ...) on an outgoing request.

```go
func WithBearerToken(token string) RequestMutator                // Authorization: Bearer <token>
func WithBasicAuth(username, password string) RequestMutator     // Authorization: Basic <base64>
func WithAPIKeyHeader(name, value string) RequestMutator          // arbitrary header, e.g. X-API-Key
func WithAPIKeyQuery(name, value string) RequestMutator           // arbitrary query param
func WithAuthCookie(name, value string) RequestMutator            // cookie (name and value only)
func WithFormCredential(name, value string) RequestMutator        // urlencoded form body field, switches method to POST
```

### CredentialLocation / ApplyCredential

`probe` package. The declarative counterpart to the mutators above, for callers that pick the placement at runtime.

```go
type CredentialLocation struct {
  In     string // CredentialLocationHeader (default), CredentialLocationCookie, CredentialLocationQuery or CredentialLocationBody
  Name   string // header/cookie/query/form-field name
  Prefix string // value prefix, e.g. "Bearer "
}

func (l CredentialLocation) WithDefaults() CredentialLocation // Authorization: Bearer when nothing is set
func (l CredentialLocation) Validate() error                  // rejects an unknown In

func NewCredentialRequest(ctx context.Context, target, value string, loc CredentialLocation) (*http.Request, error)
func ApplyCredential(req *http.Request, value string, loc CredentialLocation) (*http.Request, error)
```

`NewCredentialRequest` builds a `GET` against `target` and applies `value` at `loc`. `ApplyCredential` places `loc.Prefix+value` on a request you already built and returns a copy; `req` is never modified and keeps its method, URL, headers, cookies and body:

- `header` / `query`: the named header or query parameter is set, replacing any existing value;
- `cookie`: the cookie is set as `WithAuthCookie` does, replacing any existing cookie of that name and keeping the others;
- `body`: as `WithFormCredential` — the method becomes `POST` and the body is replaced by a urlencoded form holding only `loc.Name`.

### Probe

`probe` package. An `http.RoundTripper` that adds a default `User-Agent`, retries with exponential backoff and jitter, honours `Retry-After` / `X-RateLimit-Reset`, and can rate-limit.

```go
func New(opts ...Option) *Probe
func (p *Probe) Client() *http.Client
func (p *Probe) RoundTrip(req *http.Request) (*http.Response, error)

func WithUserAgent(ua string) Option          // default for requests that set none; a caller-set User-Agent is never overridden
func WithMaxRetries(n int) Option             // 0 = a single attempt (default 3)
func WithRetryDelay(d time.Duration) Option   // base backoff delay, capped at 60s (default 500ms)
func WithTransport(t http.RoundTripper) Option
func WithTimeout(d time.Duration) Option      // timeout of Client(), retries included (default 30s)
func WithRetryNonIdempotent() Option          // also retry POST/PATCH on network errors and 503
func WithRateLimiter(l *rate.Limiter) Option  // waits before every attempt, retries included

var ErrMaxRetriesExceeded error
```

Non-idempotent requests are retried on `429` only, unless `WithRetryNonIdempotent` is set. `RoundTrip` does not modify the request it is given (it reads the body through `GetBody` when set), and sends an empty body with a known zero length rather than chunked. `X-RateLimit-Reset` is read as an epoch timestamp, or as seconds until reset when below 10⁹.

### Do / DoResponse

`probe` package. Send a request and read the whole response, with the body capped in memory.

```go
const DefaultMaxBodySize = 10 << 20 // 10 MiB

type Response struct {
  StatusCode int
  Header     http.Header
  Body       []byte
  Duration   time.Duration
  Truncated  bool // Body holds only the first bytes of a longer response
}

type DoOption func(*doConfig)
func WithMaxBodySize(n int64) DoOption // n <= 0 means unlimited

func DoResponse(ctx context.Context, client *http.Client, req *http.Request, opts ...DoOption) (Response, error)
func Do(ctx context.Context, client *http.Client, req *http.Request) (statusCode int, header http.Header, body []byte, duration time.Duration, err error)
```

`Do` is deprecated: it is `DoResponse` with the default cap and no truncation signal. Use `DoResponse`.

### CaptureSnapshot

Sends the request returned by a `probe.RequestBuilder` via `probe.DoResponse` and returns the response as a `Snapshot`: status, headers, body (capped at `probe.DefaultMaxBodySize`, with `Truncated` set when cut), duration and `BodyHash`. The building block for a baseline — typically a request to a random, certainly-absent path, so a catch-all "soft 404" can be told apart from a real page with `CompareSimilarity`.

```go
func CaptureSnapshot(ctx context.Context, p *probe.Probe, build probe.RequestBuilder) (Snapshot, error)
```

### ProbeAndCompareBaseline

Captures the request returned by a `probe.RequestBuilder` (see [CaptureSnapshot](#capturesnapshot)) and compares it against the baseline stored under `baselineID`. Useful for one-off probes (credential swaps, header/param tampering, auth-bypass checks) that don't need the full `NewBaselineCheck` wiring.

```go
func ProbeAndCompareBaseline(ctx context.Context, p *probe.Probe, build probe.RequestBuilder, store ResultStore, baselineID CheckID, comparators ...BaselineComparator) (Snapshot, bool, error)
```

With no comparators, only a change in status code counts as a deviation (`CompareStatusCode`). Otherwise every comparator is applied and the response deviates if any of them reports an observation, so comparators compose. Returns the captured `Snapshot` and whether it deviated. Building a `Result`/`Observation` from that is left to the caller.

The baseline is read with `GetData[Snapshot]`. If none is stored it returns the captured snapshot, `false` and `ErrNoBaseline` (wrapped with the check ID), rather than comparing against an empty `Snapshot`.

### Check

A check to execute.

```go
type Check struct {
  ID          CheckID
  Name        string
  Description string
  Link        string
  Tags        []string
  DependsOn   []CheckID
  Conditions  []Condition

  // Security metadata, mirrored from checkdef.CheckDef. Descriptive only;
  // read by the engine for run-time check selection (WithMinCVSSScore, ...).
  CVSSVector string
  CVSSScore  float64
  CWEID      string
  CAPECID    string
  OWASP      string

  Skip SkipDecision

  Scope       CheckScope
  Run         CheckFunc
  RunResource ResourceCheckFunc

  // Variants: run the same check once per variant, instead of Run/RunResource.
  Variants           []string
  VariantMode        VariantMode
  RunVariant         VariantCheckFunc
  RunResourceVariant VariantResourceCheckFunc
  VariantTimeout     time.Duration
  VariantConcurrency int

  Timeout     time.Duration
  Concurrency int
}

type CheckFunc func(ctx context.Context, target Target, store ResultStore) (Result, error)
type ResourceCheckFunc func(ctx context.Context, target Target, resource Resource, store ResultStore) (Result, error)
```

**Fields:**
- `ID`: Unique identifier (required)
- `Name` / `Description` / `Link` / `Tags`: descriptive metadata (optional)
- `DependsOn`: IDs of the checks that must finish first (optional)
- `Conditions`: the check runs only if all of them are true (optional)
- `CVSSVector` / `CVSSScore` / `CWEID` / `CAPECID` / `OWASP`: security metadata (optional), populated automatically when the check is built from a `CheckDef`; used by the metadata `RunOption`s below
- `Skip`: a [`SkipDecision`](#skipdecision) evaluated before the check runs (optional)
- `Scope`: `ScopeGlobal` (default) or `ScopePerResource`
- `Run`: Function to run for global checks (required if `Scope == ScopeGlobal` and `Variants` is empty)
- `RunResource`: Function to run for per-resource checks (required if `Scope == ScopePerResource` and `Variants` is empty)
- `Variants`: Attempt variants of the same check (e.g. `alg: none` casings); when set, `RunVariant`/`RunResourceVariant` is used instead of `Run`/`RunResource`
- `VariantMode`: `VariantsSequential` (default) or `VariantsParallel` — how `Variants` are executed
- `RunVariant`: Function invoked once per variant (required if `Scope == ScopeGlobal` and `Variants` is non-empty)
- `RunResourceVariant`: Function invoked once per variant, per resource (required if `Scope == ScopePerResource` and `Variants` is non-empty)
- `VariantTimeout`: Max execution time of each variant on its own (optional); `Timeout` still bounds the variant set as a whole
- `VariantConcurrency`: Max variants in flight at once in `VariantsParallel` mode (optional, unlimited when `0`)
- `Timeout`: Max execution time of each invocation of the run function — per resource for a per-resource check, and for the whole variant set when `Variants` is set (use `VariantTimeout` to bound each variant). Falls back to the engine default (30s, see [`WithDefaultTimeout`](#withdefaulttimeout)) when `0`
- `Concurrency`: Max resources run at once for this check; falls back to `WithMaxResourceConcurrency` when `0`

**Per-resource results.** A `ScopePerResource` check is recorded once per resource, readable with `store.GetForResource(id, resourceID)`. `store.Get(id)` returns a rolled-up check-level `Result` for it, available once every resource has run: its `Observations` are all the resources' observations, its `Err` is the first resource error, and it is `Skipped` only if every resource was skipped. `Data` and `Resources` are not aggregated; read them per resource. This is what lets `IfCheckPassed`, `IfCheckObserved` and `IfCheckSkipped` work on a per-resource dependency. The aggregate is not counted in `ScanSummary`.

**Concurrency.** A check holds one slot of `WithMaxConcurrency` for as long as it runs, including while a per-resource check fans out, so up to `WithMaxConcurrency × WithMaxResourceConcurrency` resource invocations can be in flight at once.

### SkipDecision

Decides at run time whether a check, or one of its resources, is skipped. The zero value never skips.

```go
func SkipAlways(reason string) SkipDecision
func SkipWhen(fn func(ctx context.Context, target Target, store ResultStore) string) SkipDecision
func SkipResourceWhen(fn func(ctx context.Context, target Target, resource Resource, store ResultStore) string) SkipDecision
```

`fn` returns a non-empty reason to skip, or `""` to run. `SkipResourceWhen` is evaluated once per resource of a `ScopePerResource` check instead of once per check. See [Skip decisions](../guides/skip-decisions/).

### Condition

A predicate that determines if a check should run, evaluated against the results of earlier dependency levels. A check runs only if all of its `Conditions` are true.

```go
type Condition func(store ResultStore) bool
```

**Constructors:**
- `IfCheckPassed(CheckID)` — run if the check ran, was not skipped, returned no error and produced no observations
- `IfCheckObserved(CheckID)` — run if the check produced at least one observation
- `IfCheckSkipped(CheckID)` — run if the check was skipped
- `All(...Condition)` — all conditions must be true
- `Any(...Condition)` — at least one must be true
- `Not(Condition)` — negate a condition

All three `IfCheck*` constructors are false when no result is recorded for the check. For a `ScopePerResource` check they use its rolled-up result (see [Check](#check)): `IfCheckPassed` holds only if every resource passed, `IfCheckObserved` if any resource observed something, `IfCheckSkipped` if every resource was skipped.

### ResultStore

Read-only view of the results recorded so far. Skip decisions, conditions and run functions receive a snapshot taken when their dependency level started, so they see the results of earlier levels only.

```go
type ResultStore interface {
  Get(id CheckID) (Result, bool)                                // a check's result; the aggregate for a per-resource check
  GetForResource(id CheckID, resourceID string) (Result, bool)  // a per-resource check's result for one resource
  Observations() []Observation                                  // every observation so far, unordered, each counted once
  Resources() []Resource                                        // every resource discovered so far
}
```

### StaticResultStore

A `ResultStore` fixture for tests: seed the results a skip decision or condition should see without running the engine.

```go
func NewStaticResultStore(results ...Result) *StaticResultStore // keyed by each Result's CheckID
func (s *StaticResultStore) WithResources(resources ...Resource) *StaticResultStore
```

A `Result` with a `ResourceID` is seeded as that resource's result of a per-resource check and is what `GetForResource(id, resourceID)` returns; `Get(id)` then returns the roll-up of those results, as the engine does. A `Result` without a `ResourceID` answers `Get`, and `GetForResource` falls back to it for a resource with no result of its own. `Observations()` is ordered by check ID, then resource ID. `Resources()` returns what `WithResources` seeded.

### RunVariants

Runs `fn` once per variant and merges the outcomes into one `Result`, the way the engine does for a check with `Variants`. For code that wraps variant checks outside the engine.

```go
func RunVariants(ctx context.Context, variants []string, mode VariantMode, fn func(context.Context, string) (Result, error)) Result
```

- `Attempts` holds one `Attempt` per variant, in the order of `variants`.
- `Observations` and `Resources` are the attempts' slices concatenated in that order; an observation with an empty `Variant` gets its variant's name.
- `Err` is the first non-nil attempt error in `variants` order (not completion order). A failing variant does not stop the others.
- `Skipped` is set only when every variant returned a skipped `Result`, with the first one's `SkipReason`; otherwise the check counts as executed.
- A panic in `fn` is recovered onto that attempt's `Err` as a `*ScanError`.
- If `ctx` is cancelled, variants that have not started do not run; each is recorded as an attempt whose `Err` is `ctx.Err()`.
- `Result.Data` is not set; each attempt's `Data` stays on its `Attempt`.

### ScanSummary

Summary of scan results, returned by `Run` / `RunScenario` and passed to `Reporter.OnScanComplete`.

```go
type ScanSummary struct {
  Target       Target
  TotalChecks  int // scheduled checks; a per-resource check counts once
  Executed     int // executions that did not fail or skip; a per-resource check counts once per resource
  Skipped      int // skip decisions, unmet conditions, and results that report Skipped (such as Skip(...))
  Failed       int // executions whose Result.Err is non-nil
  Observations []Observation
  Results      []Result // ordered by dependency level, then check ID, then resource ID
  Duration     time.Duration
  Err          error
}
```

### Reporter

Callback interface for tracking scan progress. Checks of one dependency level run concurrently, so `OnCheckStart` and `OnCheckComplete` can be called from several goroutines at once; implementations must be safe for concurrent use.

```go
type Reporter interface {
  OnScanStart(target Target, totalChecks int)
  OnCheckStart(check Check, target Target, resource *Resource)
  OnCheckComplete(result Result)
  OnScanComplete(summary ScanSummary)
}
```

A skipped check is reported with `OnCheckComplete` only, without a preceding `OnCheckStart`. A per-resource check is reported once per resource, with `resource` set.

**Implementations:**
- `reporters.NoopReporter` — does nothing (useful as a base to embed)
- `reporters.TextReporter` — `NewTextReporter(w io.Writer)`: one human-readable line per finished check, its observations indented beneath, and a summary
- `reporters.JSONReporter` — `NewJSONReporter(w io.Writer)`: JSON Lines with `scan_start`, `check_complete` and `scan_complete` events
- `reporters.OTelReporter` — emits spans and metrics via OpenTelemetry (`github.com/cerberauth/harnessx/reporters`)

`TextReporter` and `JSONReporter` are safe for concurrent use, and an `Err()` method returns the first write error; a write error never interrupts the scan.

### ResourcePlanReporter

Optional `Reporter` extension. A reporter that also implements it learns how many resources each `ScopePerResource` check fans out over — enough, together with `OnScanStart`'s `totalChecks`, to size a progress bar.

```go
type ResourcePlanReporter interface {
  OnResourcesDiscovered(check Check, resources int)
}
```

Called once per per-resource check, just before its first run; not called when the check is skipped for lack of resources. Calls may overlap with each other and with other `Reporter` methods.

### OTelReporter

```go
// reporters sub-package
func NewOTelReporter(ctx context.Context, tracer trace.Tracer, meter metric.Meter, opts ...OTelOption) (*OTelReporter, error)

type OTelOption func(*otelConfig)

func WithPrefix(prefix string) OTelOption
```

Metrics: `{prefix}.check.duration`, `{prefix}.check.executions`, `{prefix}.observations`, `{prefix}.scan.duration` (default prefix: `"harnessx"`). `NewOTelReporter` returns an error if an instrument cannot be created.

Spans form a tree: a `{prefix}.scan` span, started in `OnScanStart` with `target.url` / `target.host` and ended in `OnScanComplete` with the totals, is the parent of one `{prefix}.check` span per check execution. A skipped check never starts, so it has no span; it is recorded as a `check.skipped` event (`check.id`, `resource.id`, `check.skip_reason`) on the scan span. A scan that fails before it starts (for example with `ErrNoChecks`) still gets a scan span carrying the error.

A reporter holds one scan span at a time, and check spans are keyed by check and resource, so use one reporter per concurrent scan; it can be reused for scans that run one after another.

### ScanError

Records a failed check — typically a recovered panic — and is stored in `Result.Err`. For a recovered panic `Stack` holds the goroutine stack, and `CheckID` is set to the failing check (including for a panic inside one variant of a `Variants` check).

```go
type ScanError struct {
  CheckID CheckID
  Cause   error
  Stack   []byte
}

func (e *ScanError) Error() string
func (e *ScanError) Unwrap() error
```

**Sentinel errors**, returned (usually wrapped with the offending check ID) by `Engine.Run` and `Engine.RunScenario`; test with `errors.Is`:

```go
var (
  ErrCycleDetected     // circular dependency found
  ErrDuplicateCheckID  // two checks have the same ID
  ErrUnknownDependency // dependency not registered (or removed by WithExclude)
  ErrNoChecks          // no check left to run
  ErrUnknownCheckID    // WithOnly names an ID that matches no check
)

// Returned by ProbeAndCompareBaseline:
var ErrNoBaseline error // nothing is stored under the baseline check's ID
```

### Engine

Main orchestration engine. Safe for concurrent `Run` / `RunScenario` calls, including a `RunScenario` issued from inside a check on the same engine.

```go
type Engine struct {
  // Private fields
}
```

**Methods:**

#### New

Create a new engine.

```go
func New(opts ...Option) *Engine
```

Checks passed with `WithChecks` are registered immediately. `New` cannot return a registration error such as a duplicate ID, so `Run` returns it (and runs nothing) instead — use `Register` to see it right away.

**Example:**
```go
engine := harnessx.New(
  harnessx.WithMaxConcurrency(4),
  harnessx.WithReporters(myReporter, otherReporter),
)
```

#### Register

Register one or more checks.

```go
func (e *Engine) Register(checks ...Check) error
```

**Returns:**
- `ErrDuplicateCheckID`, wrapped with the ID, if a check with the same ID is already registered or repeated in `checks`.
- an error naming the check if it cannot run: an unknown `Scope`, a per-resource skip decision (`SkipResourceWhen`) on a `ScopeGlobal` check, or no run function for its `Scope` and `Variants`.

Registration is all or nothing: no check from `checks` is added when one is rejected. Unknown dependencies and cycles span several checks, so they are reported by `Run`; their errors name the check and the missing dependency, or the checks that could not be ordered.

**Example:**
```go
err := engine.Register(check1, check2)
if err != nil {
  panic(err)
}
```

#### Run

Execute all registered checks against a target, optionally narrowed for this call by `RunOption`s.

```go
func (e *Engine) Run(ctx context.Context, target Target, opts ...RunOption) (ScanSummary, error)
```

**Returns:**
- `ScanSummary` with counts of executed, failed and skipped checks. It is returned alongside any error, and `Reporter.OnScanComplete` is always called.
- `ErrNoChecks` if no check is left to run
- `ErrUnknownCheckID`, naming the IDs, if `WithOnly` names a check that does not exist
- `ErrDuplicateCheckID`, `ErrUnknownDependency` or `ErrCycleDetected` for an invalid graph — including `ErrUnknownDependency` if `WithOnly`/`WithExclude` drops a check another selected check depends on, and `ErrDuplicateCheckID` for a duplicate among the `WithChecks` checks passed to `New`
- the same invalid-check errors as `Register`, for checks that never went through it (a `Scenario`'s checks)
- the context's error if `ctx` is cancelled

A failing or panicking check does not make `Run` return an error: it is counted in `ScanSummary.Failed` and its error is on its `Result`.

**Example:**
```go
ctx := context.Background()
summary, err := engine.Run(ctx, target)
if err != nil {
  println("Scan error:", err)
}

// Only run these checks this time.
summary, err = engine.Run(ctx, target, harnessx.WithOnly("auth-check", "schema-check"))

// Run everything except these.
summary, err = engine.Run(ctx, target, harnessx.WithExclude("slow-check"))
```

#### RunScenario

Execute the checks of a `Scenario` instead of the registered ones, using the engine's concurrency limits and default timeout. It neither reads nor changes the engine's registered checks. `RunOption`s narrow `scenario.Checks` exactly as they narrow registered checks in `Run`.

```go
func (e *Engine) RunScenario(ctx context.Context, target Target, scenario Scenario, opts ...RunOption) (ScanSummary, error)

type Scenario struct {
  ID          string
  Name        string
  Description string
  Tags        []string
  Checks      []Check
  Reporters   []Reporter // when non-empty, used instead of the engine's reporters for this call
}
```

See [Scenarios](../guides/scenarios/).

## Run Options

### WithRunReporters

Gives one `Run` or `RunScenario` call its own reporters, replacing the engine's (`WithReporters`) and, for `RunScenario`, `Scenario.Reporters`. Calling it more than once adds to the list.

```go
func WithRunReporters(reporters ...Reporter) RunOption
```

### WithOnly

Restricts a `Run` call to the given check IDs.

```go
func WithOnly(ids ...CheckID) RunOption
```

`Run` and `RunScenario` return `ErrUnknownCheckID` (naming them) if an ID matches no check, so a typo cannot silently select nothing.

### WithExclude

Removes the given check IDs from a `Run` call. Wins over `WithOnly` if an ID appears in both — including over the dependency pull-in of the metadata filters below.

```go
func WithExclude(ids ...CheckID) RunOption
```

### Metadata filters

Select checks by their security metadata instead of by ID. All of these are
AND-combined with each other and with `WithOnly`. A check that a selected
check `DependsOn` is kept even when it fails the filter, so the dependency
graph stays valid; only `WithExclude` drops a dependency.

```go
func WithFilter(keep func(Check) bool) RunOption // arbitrary predicate

func WithMinCVSSScore(min float64) RunOption      // CVSSScore >= min
func WithMaxCVSSScore(max float64) RunOption      // CVSSScore <= max
func WithCVSSScoreRange(min, max float64) RunOption

func WithCVSSVector(vectors ...string) RunOption  // case-insensitive, any of
func WithCWEID(ids ...string) RunOption           // case-insensitive, any of
func WithCAPECID(ids ...string) RunOption         // case-insensitive, any of
func WithOWASP(ids ...string) RunOption           // case-insensitive, any of
```

`FilterChecks` applies run options to a slice of checks the way `Run` does and returns the checks that would run, dependencies included:

```go
func FilterChecks(checks []Check, opts ...RunOption) []Check
```

```go
// Critical-only sweep, dependencies pulled in automatically.
summary, err := engine.Run(ctx, target, harnessx.WithMinCVSSScore(9.0))

// Everything mapped to a specific OWASP API category or CWE.
summary, err := engine.Run(ctx, target,
    harnessx.WithOWASP("API2:2023"),
    harnessx.WithCWEID("CWE-287", "CWE-345"),
)
```

## Options

### WithMaxConcurrency

Set max concurrent checks per dependency level. The limit applies to each `Run` / `RunScenario` call separately; it is not shared across calls on the same engine.

```go
func WithMaxConcurrency(n int) Option
```

**Default:** `runtime.NumCPU()`. Non-positive values are ignored.

### WithMaxResourceConcurrency

Set max concurrent resources per per-resource check. `Check.Concurrency` overrides it for one check.

```go
func WithMaxResourceConcurrency(n int) Option
```

**Default:** `runtime.NumCPU()`. Non-positive values are ignored.

A per-resource check keeps its `WithMaxConcurrency` slot while it fans out, so up to `WithMaxConcurrency × WithMaxResourceConcurrency` resource invocations can run at once.

### WithReporters

Set one or more reporters. They are used by `Run`, and by `RunScenario` calls whose `Scenario.Reporters` is empty. Every reporter receives every callback.

```go
func WithReporters(reporters ...Reporter) Option
```

**Default:** no reporters.

### WithDefaultTimeout

Set the timeout applied to checks that leave `Check.Timeout` at zero.

```go
func WithDefaultTimeout(d time.Duration) Option
```

**Default:** `30s`. Non-positive values are ignored.

### WithResourceMerge

Choose what happens when a check discovers a resource whose `ID` is already known. The resource is never added twice, so per-resource checks run once per ID; the merge function decides which version is kept.

```go
type ResourceMergeFunc func(existing, incoming Resource) Resource

func KeepFirstResource(existing, _ Resource) Resource  // default
func KeepLastResource(_, incoming Resource) Resource
func WithResourceMerge(fn ResourceMergeFunc) Option    // nil is ignored
```

Checks in the same dependency level run concurrently, so which of their versions is "last" is not deterministic; make one check depend on the other to fix the order.

### WithChecks

Register checks when the engine is created. `New` cannot return a registration error such as a duplicate ID, so `Run` returns it instead and runs nothing; use `Register` to see it right away.

```go
func WithChecks(checks ...Check) Option
```

## Execution Flow

1. **Validate**: Check for duplicates, missing dependencies, cycles
2. **Topological Sort**: Order checks into dependency levels using Kahn's algorithm
3. **Execute Levels**: For each level:
   - Take snapshot of prior results
   - Run independent checks in parallel (bounded by `MaxConcurrency`)
   - Wait for level to complete
4. **Per-Resource Checks**: For checks with `ScopePerResource`:
   - For each resource from dependencies:
     - Run check (bounded by `MaxResourceConcurrency`)
5. **Callbacks**: Call reporter on each start/complete, then on scan complete

## Error Handling

### Panics

If a check panics, the panic is recovered and recorded as a `*ScanError` on that check's `Result.Err` (and, for a variant, on its `Attempt.Err`). The check counts as failed and the scan continues; `Run` does not return an error for it.

### Timeouts

Each invocation of a check's run function gets its own timeout: `Check.Timeout`, or the engine default when zero. The context passed to the function is cancelled when it expires; a function that honours it and returns `ctx.Err()` fails with `context.DeadlineExceeded`, and the scan continues. A check with `Variants` shares one timeout across all its variants.

### Context Cancellation

If the root context is canceled, running checks are canceled and no further level starts. The scan returns the context error alongside the `ScanSummary`, in which every check that did not get to run is recorded as skipped with the reason `"scan cancelled"`, so `Executed + Skipped + Failed` still accounts for all of them.

## Common Patterns

### Check if scan succeeded

```go
summary, err := engine.Run(ctx, target)
if err != nil {
  panic(err)
}

if summary.Failed > 0 {
  println("Issues found!")
}
```

### Collect observations

```go
summary, err := engine.Run(ctx, target)
if err != nil {
  return err
}
for _, o := range summary.Observations {
  fmt.Printf("%s: %s\n", o.CheckID, o.Title)
}
```

Or, to stream them as checks finish, implement `Reporter.OnCheckComplete` (guarding shared state with a mutex, since checks run concurrently).

### Timeout entire scan

```go
ctx, cancel := context.WithTimeout(context.Background(), 60*time.Second)
defer cancel()

summary, err := engine.Run(ctx, target)
```
