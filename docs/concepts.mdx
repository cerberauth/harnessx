## Checks

A `Check` is a unit of work. Each check:
- Has a unique ID across the engine
- Runs within a scope (`ScopeGlobal` or `ScopePerResource`)
- Can depend on other checks
- Returns a `Result` with pass/fail status and optional observations

```go
type Check struct {
  ID         CheckID
  Scope      CheckScope
  Timeout    time.Duration
  DependsOn  []CheckID
  Run        func(context.Context, Target) (Result, error)
  RunResource func(context.Context, Target, Resource) (Result, error)
}
```

## Check Definitions

For a reusable check package, hand-assembling a `Check`'s `ID`, `Name`, `Description`, `Link`, `Tags`, and `DependsOn` in Go gets repetitive. The `checkdef` subpackage (`github.com/cerberauth/harnessx/checkdef`) parses that metadata from an embedded YAML, TOML, or JSON file:

```go
import "github.com/cerberauth/harnessx/checkdef"

//go:embed check.yaml
var checkYAML []byte

var def = checkdef.MustParseCheckDefYAML("algnone", checkYAML)

var Check = checkdef.NewCheck(def, run) // Scope: ScopeGlobal, ID/Name/.../DependsOn wired from def
```

`MustParseCheckDefYAML` / `MustParseCheckDefTOML` / `MustParseCheckDefJSON` each panic (prefixed with the given `pkg` name) on malformed input, since definitions are normally parsed once at `init()` time — a bad definition file is a build-time bug, not a runtime error.

`NewCheck` (`ScopeGlobal`) and `NewResourceCheck` (`ScopePerResource`) turn a `CheckDef` plus a run function into a `harnessx.Check` without hand-copying every metadata field. `WithSkip`, `WithConditions`, `WithTimeout`, and `WithConcurrency` set the remaining optional `Check` fields via functional options:

```go
var Check = checkdef.NewCheck(def, run,
    checkdef.WithSkip(harnessx.SkipWhen(isOffline)),
    checkdef.WithTimeout(10*time.Second),
)
```

`checkdef` is a separate package so the root `harnessx` package keeps zero third-party dependencies; only code that imports `checkdef` pulls in a YAML/TOML parser.

## Execution Scopes

  </Card>
  <Card title="ScopePerResource" icon="puzzle">
    Runs **once per discovered resource**. Examples: check each endpoint, each user, each bucket.

### Example: Global check

```go
harnessx.Check{
  ID:    "tls-valid",
  Scope: harnessx.ScopeGlobal,
  Run: func(ctx context.Context, target harnessx.Target) (harnessx.Result, error) {
    // Check target once
    return harnessx.Result{Passed: true}, nil
  },
}
```

### Example: Per-resource check

```go
harnessx.Check{
  ID:    "endpoint-auth",
  Scope: harnessx.ScopePerResource,
  RunResource: func(ctx context.Context, target harnessx.Target, res harnessx.Resource) (harnessx.Result, error) {
    // Check each resource (e.g., each API endpoint)
    return harnessx.Result{Passed: true}, nil
  },
}
```

## Resources

A `Resource` is discovered by a global check and consumed by per-resource checks.

```go
type Resource struct {
  ID     string
  Type   string
  Metadata map[string]any
}
```

Global checks emit resources:

```go
harnessx.Check{
  ID:    "discover-endpoints",
  Scope: harnessx.ScopeGlobal,
  Run: func(ctx context.Context, target harnessx.Target) (harnessx.Result, error) {
    // Discover resources
    resources := []harnessx.Resource{
      {ID: "/api/users", Type: "endpoint"},
      {ID: "/api/posts", Type: "endpoint"},
    }

    return harnessx.Result{
      Passed:    true,
      Resources: resources,
    }, nil
  },
}
```

Downstream per-resource checks receive them:

```go
harnessx.Check{
  ID:        "validate-endpoint",
  Scope:     harnessx.ScopePerResource,
  DependsOn: []harnessx.CheckID{"discover-endpoints"},
  RunResource: func(ctx context.Context, target harnessx.Target, res harnessx.Resource) (harnessx.Result, error) {
    // Check each endpoint
    return harnessx.Result{Passed: true}, nil
  },
}
```

## Dependencies

Checks can depend on other checks. The engine automatically sorts them topologically and runs independent checks in parallel.

```go
// B depends on A
harnessx.Check{
  ID:        "b",
  DependsOn: []harnessx.CheckID{"a"},
  // ...
}
```

The engine detects and rejects:
- **Cycles**: A → B → A
- **Unknown dependencies**: B depends on non-existent check C
- **Duplicate IDs**: two checks with the same ID

## Scenarios

A `Scenario` is a named, ordered subset of checks. Use `Engine.RunScenario` to execute only those checks using the engine's configured reporters, concurrency limits, and default timeout. The engine's registered check list is ignored — `Scenario.Checks` is fully self-contained.

```go
type Scenario struct {
  ID          string
  Name        string
  Description string
  Tags        []string
  Checks      []Check
}
```

Checks can be shared across scenarios by referencing the same `CheckFunc` variable from multiple `Check` values, each with its own `DependsOn` wiring:

```go
var checkAuthFn harnessx.CheckFunc = func(...) (harnessx.Result, error) { ... }

// REST: auth after endpoint discovery
var restAuth = harnessx.Check{ID: "rest-auth", DependsOn: []harnessx.CheckID{"rest-discovery"}, Run: checkAuthFn}

// GraphQL: same logic, different position in the graph
var gqlAuth  = harnessx.Check{ID: "gql-auth",  DependsOn: []harnessx.CheckID{"gql-introspection"}, Run: checkAuthFn}
```

See the [Scenarios guide](/guides/scenarios) for the full API and patterns.

## Conditions

Conditions allow you to skip checks based on prior results.

```go
check := harnessx.Check{
  ID:        "auth-method",
  Condition: harnessx.IfCheckPassed("tls-valid"),
  // Only runs if "tls-valid" passed
}
```

Available conditions:
- `IfCheckPassed(id)` — run if check passed
- `IfCheckObserved(id)` — run if check produced at least one observation
- `IfCheckSkipped(id)` — run if check was skipped
- `All(conds...)` — all conditions must be true
- `Any(conds...)` — at least one condition must be true
- `Not(cond)` — negate a condition

## Skip Decisions

`Skip` gates whether a check (or, for `ScopePerResource` checks, an individual resource) runs, evaluated before `Conditions`:

```go
func SkipAlways(reason string) SkipDecision
func SkipWhen(fn func(ctx context.Context, target Target, store ResultStore) string) SkipDecision
func SkipResourceWhen(fn func(ctx context.Context, target Target, resource Resource, store ResultStore) string) SkipDecision
```

- `SkipAlways` / `SkipWhen` skip the whole check (all resources at once, for `ScopePerResource`).
- `SkipResourceWhen` is evaluated once per resource, so different resources can be skipped for different reasons.
- With no per-resource decision set, per-resource evaluation falls back to the check-wide one.

See the [Skip Decisions guide](/guides/skip-decisions) for examples.

## Observations

An `Observation` describes an issue or noteworthy outcome found by a check.

```go
type Observation struct {
  CheckID     CheckID
  ResourceID  string
  Title       string
  Description string
  Evidence    string
  Metadata    map[string]string
}

type Result struct {
  Skipped      bool
  Observations []Observation
  Resources    []Resource
}
```

## Baseline Comparison

A `Baseline` (`Snapshot{StatusCode int, Data any}`) captures the expected response for a resource. `NewBaselineCheck` compares it against a freshly captured response and turns any deviation into `Observation`s — the canonical case being an endpoint that normally returns `401` but returns `200` because of a broken authorization check.

```go
type BaselineSource func(ctx context.Context, target Target, resource Resource, store ResultStore) (Baseline, bool)
type BaselineComparator func(baseline, current Snapshot) []Observation

func StaticBaseline(b Baseline) BaselineSource
func BaselineFromResource() BaselineSource
func BaselineFromCheck(id CheckID) BaselineSource
func CompareStatusCode(baseline, current Snapshot) []Observation // default comparator

func NewBaselineCheck(cfg BaselineCheckConfig) Check
func CaptureBaselineCheck(id CheckID, name string, capture func(ctx context.Context, target Target, resource Resource, store ResultStore) (Snapshot, error)) Check

// ScopeGlobal counterparts, for targets with no per-resource dimension.
func StaticGlobalBaseline(b Baseline) GlobalBaselineSource
func BaselineFromGlobalCheck(id CheckID) GlobalBaselineSource
func NewGlobalBaselineCheck(cfg GlobalBaselineCheckConfig) Check
func CaptureGlobalBaselineCheck(id CheckID, name string, capture GlobalCapture) Check

// probe package: build a request, then apply named mutators (WithBearerToken,
// WithBasicAuth, WithAPIKeyHeader, WithAPIKeyQuery, WithAuthCookie, WithFormCredential, ...).
func NewRequest(ctx context.Context, method, target string, body io.Reader, mutators ...probe.RequestMutator) (*http.Request, error)
func ProbeAndCompareBaseline(ctx context.Context, p *probe.Probe, build probe.RequestBuilder, store ResultStore, baselineID CheckID) (Snapshot, bool, error)
```

- The baseline comes from a **baseline probe** (`CaptureBaselineCheck` + `BaselineFromCheck`) captured at runtime, or is **defined manually** (`StaticBaseline`, or `BaselineFromResource` reading `Resource.Data` set at discovery time).
- `Compare` defaults to `CompareStatusCode` but can be overridden with any function to judge headers, body, or other data carried in `Snapshot.Data`.
- A resource with no resolvable baseline is skipped rather than compared.
- For `ScopeGlobal` checks (no per-resource dimension), use `NewGlobalBaselineCheck`/`CaptureGlobalBaselineCheck` — same API, minus the `Resource` param.
- For a credential-placement probe (swap/omit a token, API key, session ID), `ProbeAndCompareBaseline` takes a `probe.RequestBuilder` and collapses request-build + send + compare into one call — no `Capture`/`Compare` wiring needed.

See the [Baseline Comparison guide](/guides/baseline) for examples.

## Execution Model

1. **Topological sort**: Engine sorts checks into dependency levels using Kahn's BFS
2. **Level execution**: Each level runs in parallel (bounded by `MaxConcurrency`)
3. **Snapshot**: Before each level, a frozen snapshot is taken of all prior results
4. **Per-resource parallelism**: Per-resource checks fan out across resources (bounded by `MaxResourceConcurrency`)
5. **Panic recovery**: If a check panics, it's recorded as a `ScanError` and the scan continues
6. **Context propagation**: All operations respect the provided `context.Context` and per-check timeouts

## Error Handling

The `Run()` method returns a `ScanError` if:
- The context is canceled
- A check times out
- A check panics
- A dependency is not found
- There are duplicate check IDs
- There are circular dependencies

Checks return regular errors for application logic failures (network errors, parsing, etc.).
